# Design decisions: email send

| #   | Decision                                                                                         | Why                                                                                                                        | Rejected                                                                          |
| --- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 1   | Stack sends only on the owner's click on Send. This replaces "Stack never sends"                 | The owner asked for one-click Send in the Inbox. A reply he must send from another app is not one click                    | Keep drafts only (the Inbox stays a list of links to Outlook)                     |
| 2   | Send is off by default, per account, in Settings > Accounts                                      | The send permission is asked for only when the owner wants it. Other accounts keep the old limits                          | Send on for every account with drafts on (a silent permission change)             |
| 3   | The send is `POST /me/messages/{id}/reply` with the comment only                                 | One call. The server supplies recipients, subject and thread, so model text can never pick a recipient                     | `createReply` + `PATCH` + `send` (three calls, two more guard exceptions)         |
| 4   | The guard binds an approval to one message id and the SHA-256 of the text                        | The text that goes out is the text the owner clicked on. No other code path holds an approval                              | An approval by id only (a different text could ride on it)                        |
| 5   | Only the owner session reaches the send route. API tokens get 403. A local process that runs as the owner's OS user counts as the owner, as on every `stack web` route | A click is the consent. A process with the owner's OS rights can already read the 0600 token file and call Graph itself, so a stronger check on this one route adds no protection | A `mail:send` token scope; a per-page secret for one route (a second auth model)  |
| 6   | With Send on, the runner keeps reply drafts on this machine, not in the mailbox                  | A reply sent from Stack would leave a stale AI draft in Outlook. The guard never deletes                                   | Mailbox drafts in both modes; delete the stale draft (a delete path)              |
| 7   | The CLI sign-in never asks for the send scope and never saves it                                 | Only the in-app setting turns Send on, so the state is one explicit choice                                                 | `--with send` (a second way to turn it on)                                        |
| 8   | No confirm step and no undo after Send                                                           | The owner asked for one click. The text is in front of him when he clicks                                                  | A confirm dialog (two clicks); a delayed send (a timer in the host)               |

# Design decisions: first-run onboarding

| #   | Decision                                                                                  | Why                                                                                                         | Rejected                                                                       |
| --- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 1   | A separate setup server, swapped for the real server on the same port                     | `startWeb` needs a repo for storage, watcher and api. Same port keeps the page and the desktop window url   | A repo-less mode inside `startWeb` (touches every route); restart the process  |
| 2   | Progress in the user config (`onboarding`), not browser storage                           | The desktop app and every browser tab share it; it survives a cleared browser                               | `localStorage` (per origin; the desktop port is random)                         |
| 3   | Save the repo at step 1, restart in demo                                                  | Demo never writes the repo, so it is the safe default while the owner decides                               | Hold repo and mode until step 2 (a closed app loses step 1)                    |
| 4   | Live needs a checked "I understand"                                                       | Live commits and pushes; a plain warning plus one deliberate act, no modal                                  | A confirm dialog (P3: no approval prompt for reversible acts; this one is not) |
| 5   | Email step shows the command, never runs sign-in                                          | Device-code sign-in needs an app id and a terminal; Stack never sends mail and must not look like it could   | An in-app OAuth flow (needs a redirect host)                                   |
| 6   | Desktop wraps `startHost` through its `startWeb` seam (`desktop/src/local.ts`)             | No change to `host.ts`, which open PR 129 also edits                                                        | New `port`/`setup` options on `startHost`                                      |
| 7   | Touch and contrast fixes in `polish.css`, scoped overrides                                | PRs 118, 124, 126 edit `inbox.css`, `views.tsx` and `styles.css` tokens; scoped rules avoid conflicts       | Token changes in `styles.css`                                                  |

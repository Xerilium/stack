# Architecture review: Stack after PRs 75-114

Date: 2026-11-10. Scope: `src/`, `web/`, `host/`, `desktop/`, `docs/`, `.xe/`. Baseline: `main` at `e85a71b` (PR 114). Lens: `.xe/architecture.md`, `.xe/engineering.md` (KISS, YAGNI, SRP, DRY), `.xe/features/stack-app/research-architecture.md`.

Effort: S = under 1 hour, M = half a day, L = a day or more. "Fixed" = done in this PR.

## TL;DR

- The ranking has one server source (`GET /rank`), but the web keeps a client mirror of the stack engine's date rules. One parity test holds them together.
- PR 114 removed the Brief view but left its model, its tests, its API route and its e2e mock.
- Engines are picked three ways. The architecture doc says the legacy engine is the default; `stack next` uses `stack`.
- Four files are at or near 1,000 lines. Each mixes several concerns.

## What is right

- One ranking: `GET /rank`, `GET /next`, `stack next` and `homeOf` all read `rankStack`. `homeOf` ranks nothing (`web/src/home.ts:48-55`).
- Storage, formatters and engines sit behind interfaces as `.xe/architecture.md` says.
- `src/core` imports nothing from `api`, `host`, `cli` or `web`.
- The OpenAPI document is generated from `ROUTES` and tested against it (`tests/api/openapi.test.ts:132`).
- The ACP seam matches the research: `AgentDriver` in `src/agents/driver.ts`, Claude on the SDK (`sdk.ts`), others over ACP (`acp.ts`).

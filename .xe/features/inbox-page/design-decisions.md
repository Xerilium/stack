# Design decisions: inbox page

| #   | Decision                                                                                         | Why                                                                                                                        | Rejected                                                                          |
| --- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 1   | Source status rides on `GET /inbox-items`, plus a light `GET /inbox-sources`                    | `GET /inbox` is the agent inbox (instructions to agents); the Inbox page already reads `/inbox-items`. The light route feeds the dot and Check connection | Adding `sources` to `GET /inbox` (wrong resource)                                  |
| 2   | Sync records in the data repo (`.stack/inbox-sources.json`), token probe on the local host only | Runners run on the Mac; the hosted app reads the repo. Records hold codes and times only, so they are safe to commit       | Hosted app reads token caches (it has none); status only in local state files     |
| 3   | Teams and Slack are listed but `planned`: never counted, no dot. GitHub too until its runner reports | Their connectors are not wired yet (no GitHub runner is scheduled). A dot the owner cannot clear, or a source that is "connected" but never syncs, is noise | Count them (dot never clears); hide them (owner cannot see what they need)        |
| 4   | "Connected" counts `ok`, `stale` and `connecting`; Inbox zero needs one `ok` and no `error` or `stale` | Signed in is progress for onboarding; only fresh syncs prove there is nothing new, and one broken mailbox makes zero untrue | Count only `ok`; zero on any one fresh source (hides an expired mailbox)           |
| 5   | Freshness in `.xe/config/stack.json` (`inbox.freshMinutes`, default 30)                          | Every host reads that config; 30 minutes is two missed 15-minute passes                                                   | User config in `~/.config/stack` (the hosted app cannot read it)                  |
| 6   | Expected accounts in `inbox.accounts`                                                            | A mailbox that was never signed in leaves no file to find; the owner lists it once and the page shows it as not connected | Guessing accounts from mail                                                       |
| 7   | The server writes `needs` and `command`; the page and the CLI only render them                   | One place for the exact human step; the CLI and the page cannot drift                                                     | Per-client step text                                                              |
| 8   | `CopyCommand` moved to `parts.tsx` and used by onboarding and the sources panel                  | Same command block, same Copy behavior, same 44 px target                                                                 | A second copy of the block                                                        |

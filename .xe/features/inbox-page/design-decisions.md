# Design decisions: inbox page

| #   | Decision                                                                                         | Why                                                                                                                        | Rejected                                                                          |
| --- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 1   | Source status rides on `GET /inbox-items`, plus a light `GET /inbox-sources`                    | `GET /inbox` is the agent inbox (instructions to agents); the Inbox page already reads `/inbox-items`. The light route feeds the nav dot | Adding `sources` to `GET /inbox` (wrong resource)                                  |
| 2   | Sync records in the data repo (`.stack/inbox-sources.json`), token probe on the local host only | Runners run on the Mac; the hosted app reads the repo. Records hold codes and times only, so they are safe to commit       | Hosted app reads token caches (it has none); status only in local state files     |
| 3   | Teams and Slack are listed but `planned`: never counted, no dot. GitHub too until its runner reports | Their connectors are not wired yet (no GitHub runner is scheduled). A dot the owner cannot clear, or a source that is "connected" but never syncs, is noise | Count them (dot never clears); hide them (owner cannot see what they need)        |
| 4   | "Connected" counts `ok`, `stale` and `connecting`; Inbox zero needs every counted source `ok` | Signed in is progress for onboarding; only fresh syncs prove there is nothing new, and one missing, broken or behind mailbox makes zero untrue | Count only `ok`; zero on any one fresh source (hides an expired mailbox)           |
| 5   | Freshness in `.xe/config/stack.json` (`inbox.freshMinutes`, default 30)                          | Every host reads that config; 30 minutes is two missed 15-minute passes                                                   | User config in `~/.config/stack` (the hosted app cannot read it)                  |
| 6   | Expected accounts in `inbox.accounts`                                                            | A mailbox that was never signed in leaves no file to find; the owner lists it once and the page shows it as not connected | Guessing accounts from mail                                                       |
| 7   | The server writes `needs` and `command`; the page and the CLI only render them                   | One place for the exact human step; the CLI and the page cannot drift                                                     | Per-client step text                                                              |
| 8   | `CopyCommand` moved to `parts.tsx` and used by onboarding                                        | Same command block, same Copy behavior, same 44 px target                                                                 | A second copy of the block                                                        |
| 9   | Inbox holds no setup UI; a quiet header link and a Fix link (on attention) go to Settings > Accounts (issue [169](https://github.com/Xerilium/stack/issues/169)) | The sources panel repeated the old connect panel's noise on a work page. Settings is the one place for accounts (`FR:settings/view.sections`) | Fold the panel to one line (still setup on a work page); keep Check connection (Settings has Retry; the page re-reads every minute) |
| 10  | Rows keep their own markup until `AskCard` ships (product-reset Stage 4)                         | Stage 4 owns the shared components; building `AskCard` here would fork it                                                   | Build `AskCard` in this change                                                    |
| 11  | The detail reads the message live from Graph on each open and stores nothing                     | The item file syncs to the data repo, so it holds summaries only. A live read keeps mail text on this machine and in the page | Message text in `.stack/inbox-items.json` (mail in git); a local body cache (a second copy to protect and expire) |
| 12  | The thread comes from three folder reads (Inbox, Sent Items, Archive) with a `conversationId` filter | These reads are already on the guard allowlist. The guard does not change                                                  | Allow `GET /me/messages` (a wider allowlist for one view)                         |
| 13  | Mail text renders as plain text through the shared `ThreadMessage` component                           | Mail is untrusted data. Plain text cannot run script, load a remote image or hide a link                                    | Sanitized HTML (a sanitizer to trust and keep current)                            |
| 14  | The selected item is page state, not a route                                                     | Small change; the split view has its own Back on a phone                                                                   | `#/inbox/<id>` (deep link; add when a view needs to link to a message)            |
| 15  | Junk is a view of the item file: kind `spam` or `newsletter`, unless the owner restored it       | No new store and no new triage class. Cold outreach is `spam` by one prompt line                                           | A `cold_outreach` class (schema, hygiene and ask changes for one label)           |
| 16  | The owner's click on a Junk action is the approval; the guard gets exactly the clicked ids         | One click must clear junk. The guard code does not change: it still moves only approved ids, only to Archive               | An ask per click (two steps for one decision); a wider guard                      |
| 17  | Junk moves to Archive, never to Deleted Items; `Not junk` is a flag on the item that passes keep   | Archive is reversible in Outlook. A flag needs no sender address in the item file                                          | Delete (not reversible); a sender allowlist                                       |

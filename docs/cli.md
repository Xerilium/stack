# CLI

`stack <command> [args] [flags]`. Refs are `tasks/<file>.md:<line>` (1-based), for example `tasks/alpha.md:12`; without a ref, commands act on the next task. Exit codes: 0 ok (including no-ops), 1 failure, 2 usage, 3 conflict, 4 no task to act on.

Global flags: `--dir <path>` (optional; default: found by walking up from the current folder, then `$STACK_DIR`, then `dir` in `~/.config/stack/config.json`), `--json`, `--no-commit`, `--remote <name>`, `--branch <name>`, `--now <ISO>`, `--help`, `--version`.

Help: `stack <command> --help` or `stack help <command>` prints one command's usage and flags; `stack --help` lists every command.

- `web`: <a id="web"></a>serve the web app on localhost (default port 4173) over a content repo (`--repo path-or-git-url`, else discovery). DEMO by default (scratch copy in `~/.config/stack/demo`, `--reset` re-copies); `--live` edits `tasks/` in your real checkout on its current branch (`--branch` asserts which), committed in batches after `--batch` minutes idle (default 5, `0` = every edit), on `POST /api/sync`, and on shutdown; pushed to `origin` when present. `web [--repo path-or-url] [--live] [--branch name] [--remote name] [--batch minutes] [--port n] [--reset] [--bind loopback|tailnet]`. `--bind tailnet` also listens on the Mac's Tailscale addresses for paired devices only ([phone access](phone-access.md)). User config `~/.config/stack/config.json` keys: `repo`, `mode` (`live`), `branch`, `remote`, `batch` (minutes), `bind`, `ics` (published calendar link), `onboarding` (setup progress). With no repo, `stack web` serves a first-run setup flow instead of failing; `--repo`, `--live`, the current folder and `STACK_REPO` still win, and the flow shows them as fixed
- `devices`: <a id="devices"></a>pair a phone with the tailnet host. `devices add <name>` prints a one-time pairing code; `devices list`; `devices revoke <id>` cuts the phone off at once. Stored in `~/.stack/tokens.json` and `devices.json` (mode 0600)
- `app`: <a id="app"></a>build Stack.app from the source checkout (`STACK_SOURCE`, else `~/.local/share/stack`) and install or update it in `/Applications` through a helper that swaps the bundle after the app exits, keeps the old one, and rolls back on failure (`~/.stack/update.log`). `install` builds, places, and opens it. `update` builds, then installs at once only when Stack is closed; when Stack runs it waits for the update mode (default: when you quit). `--check` changes nothing (exit 4 when up to date); `--install` quits, swaps, and reopens now; `--no-build` uses the build that is there. `status` shows the installed and ready builds. See [desktop-install.md](desktop-install.md#update). `app install [--no-build] | update [--check | --install] [--no-build] | status [--source dir]`
- `graph`: <a id="graph"></a>one-time Microsoft Graph sign-in (device code) so `stack web` shows the live calendar. Read scopes only (`--with calendar,mail,drafts`); `Mail.Send` is refused. The token stays in `~/.config/stack/graph-token.json` (`--cache`, mode 0600). `graph login --client-id <id> [--tenant t] [--account addr] [--with calendar,mail,drafts] [--cache path] | status | logout` (`--account` keeps a separate token per mailbox)
- `email`: <a id="email"></a>one triage pass on the signed-in mailbox: rules first, Haiku classifies, Sonnet drafts in your voice (drafts only, never sends), archive/spam/unsubscribe asks act only after you answer. Runs where Claude Code runs (launchd or a scheduled task). `run` takes a lock and stops before any model call when one delta exceeds `--max` (default 200); `--dry-run` writes nothing; `--dry-run --offline [--fixture f.json]` also needs no network, sign-in or `claude`. Setup steps: `docs/email-runner.md`. `voice` learns your style from Sent items (plus `--extra file.json` from elsewhere) into `$STACK_DATA_DIR`. `email run [--all] [--mode observe|drafts] [--max n] [--dry-run] [--project p] | voice [--extra file.json] | status [--account a] | schedule [--remote origin]`
- `init`: <a id="init"></a>create repo, tasks/, and config. `init`
- `add-project`: <a id="add-project"></a>create a project file. `add-project <name> [--description t] [--repo url] [--alias a,b] [--priority n] [--capacity Block=h,..] [--weekly-capacity n] [--file name] [--force] [--queries] [--no-update]`
- `add`: <a id="add"></a>add a task. `add <project> <text...> [--section name] [--parent ref]`
- `capture`: <a id="capture"></a>add a task from a phrase (e.g. "call dentist tomorrow 30m #alpha"). `capture <text...> [--project name] [--section name] [--dry-run]`
- `next`: <a id="next"></a>print the top task, or the first n ranked tasks (the same order as the web Home and `GET /api/rank`; overrides in [ranking.md](ranking.md)). Priority action rows (`pri:<rank>`, from the newest `pris note` after `Michael:`) come first, in the order of the day; then tasks linked to a priority; then the rest. `--daily` lists each project with its pick and `done=yes|no` for today. `next [--top n | --daily]`
- `start`: <a id="start"></a>mark in progress. `start [ref] [--expect t] [--queries] [--no-update]`
- `complete`: <a id="complete"></a>check off (rolls recurring rows). `complete [ref] [--summary t] [--remove] [--expect t] [--queries] [--no-update]`
- `skip`: <a id="skip"></a>park a task (alias: park). `skip [ref] [--expect t] [--queries] [--no-update]`
- `retitle`: <a id="retitle"></a>edit a task row text in place; checkbox, indent, children, notes, history, and old status/priority/effort/impact marks at the row start or end stay unless the new text has the same kind there (pass tags like `📅 Nov 5` in `--text`). Agents use it instead of add + `complete --remove`. Exit 3 when `--expect` differs. `retitle <ref> --text t [--expect t] [--no-update]`
- `check`: <a id="check"></a>the task quality gate on one row: prints `<ref> <score>/4 actionable` or `<ref> <score>/4 missing: <checks>` (`next`, `doneWhen`, `context`, `single`); exit 0 at 4, else 1; never writes. It also runs the task lint on the row: an issue adds ` lint: <rules>` and gives exit 1. Agents run it after they create or edit a task ([task-rubric.md](task-rubric.md)). `check <ref> [--json]`
- `lint`: <a id="lint"></a>the task bloat lint on every open row in `tasks/` (or one file with `--project`): one `<path>:<line> <rule> <message>` line per issue, then `<n> issues in <m> files`, or `no issues`. Rules: `title-length` (more than 120 characters), `title-status` (status words or dates in the title), `title-parens` (more than 1 parenthetical), `detail-nesting` (detail after a dash, or a nested line that is not a bullet). Exit 0 with no issue, else 1; never writes. `add`, `capture`, and `retitle` refuse a title that breaks a title rule (exit 2). See [task-rubric.md](task-rubric.md). `lint [--project name] [--json]`
- `note`: <a id="note"></a>append a nested note bullet under a task; children stay; no summary refresh; exit 3 when `--expect` differs. `note add <ref> --text t [--expect t]`
- `triage`: <a id="triage"></a>show/set autonomy, add 🪄/🙋 subtasks. `triage <ref> [--autonomy none|triage|assist|full] [--agent t] [--human t] [--priority e] [--effort e] [--impact e]`
- `park`: <a id="park"></a>same as skip. `park [ref] [--expect t] [--queries] [--no-update]`
- `resume`: <a id="resume"></a>unpark the first parked task. `resume [ref] [--expect t] [--queries] [--no-update]`
- `suspend`: <a id="suspend"></a>hide until later. `suspend [ref] [--days n | --hours n] [--expect t] [--queries] [--no-update]`
- `set`: <a id="set"></a>set emojis and checkbox. `set <ref> [--status e] [--priority e] [--effort e] [--impact e] [--checkbox complete|incomplete] [--suspend v] [--remove-emojis] [--expect t]`
- `tag`: <a id="tag"></a>set the 🔓 unblocker and 📅 due tags the autopri engine reads. `tag <ref> [--unblocker yes|no] [--due "MMM d"|none] [--expect t]`
- `rank`: <a id="rank"></a>ranked tasks the owner must do (agent rows are left out; a row overdue 3+ days with no commit in 3+ days is `stale`, capped at 500); `pris` boosts tasks linked to `~/.stack/pris.json` by priority order ([scoring-bakeoff-pris.md](scoring-bakeoff-pris.md)); `--explain` shows why each task has its place (stack: due tier and stale details, plus the count of dropped agent rows; autopri, pris: score parts and the priority served); `--truth` lists ground-truth items to tag or add. `rank [--engine autopri|pris|stack] [--top n] [--explain [--truth file]] [--daily]` (the default order is priority first, as `next`; an explicit engine keeps its own order)
- `asks`: <a id="asks"></a>ask queue for the owner; agents `put` and `handle` asks, read answers with `list`. See [docs/asks.md](asks.md). `asks put <key> --ask t --kind k --from agent [--project --why --recommend --options "A|B" --default --by --reversible yes|no --link --priority --effort --blocks --detail-file p --reopen --flow slug --seq n --ref project:line --apply "<action>" --applies "a|b"] | list [--state s] | handle <key> --outcome o [--note --reply] | archive [--days n]`
- `report`: <a id="report"></a>send an agent status report (top 3, asks on the owner, blockers, progress) to the desktop host, or write `~/.stack/reports.json` when no host runs; never git; its asks show in Needs you. See [docs/report.md](report.md). `report --agent <name> --project <p> [--file report.json] [--json]` (JSON on stdin when no `--file`)
- `prs`: <a id="prs"></a>open PRs you review or move, by group: processing (Autopilot), waiting on you, pending (yours, no Autopilot), paused. Each line shows your next action (Validate, Sign off, Approve, Publish review, Enable Autopilot), else the owner (you, a reviewer, CI, runner), and the link. `--json` adds `nextAction`, `specLines`, `pinned`, `detail`, and the `summary`. Needs `GITHUB_TOKEN`; reads `~/.stack/pr-priority.json` for ranks and Sweep Manager reports. Read only. `prs [--group processing|waiting|pending|paused] [--project p] [--json]` (`--project` takes a project or a repo) `--sort spec-lines` drops Autopilot rows and puts the fewest spec lines first (`.xe/`, `spec.md`, `docs/*.md`; cached per head SHA in `~/.stack/pr-facts.json`); 🔬 marks a PR that needs live validation
- `feedback`: <a id="feedback"></a>owner feedback on the app in `~/.stack/feedback.jsonl` (one JSON line each; [feedback.md](feedback.md)). No repo. `feedback add "<text>" [--route r]`, `feedback list [--since id]`, `feedback done <id>` (unknown id exits 4).
- `qm`: <a id="qm"></a>the weekly QM (quota-maxxing) plan in `~/.stack/qm-plan.json` (never git; schema in [qm-plan spec](../.xe/features/qm-plan/spec.md)). No repo. `qm [--json]` prints it; `qm put --file plan.json [--json]` validates and replaces it (bad input exits 2 with every issue). The app shows it at `#/qm`.
- `sessions`: <a id="sessions"></a>Claude app sessions on this machine. Read-only on the app store; facts cached by mtime in `~/.stack/sessions.json`. Prints counts, the ranked Needs-you list (waiting, stuck) with `claude://` links, and the number of archive candidates (`--json` lists them). `sessions [--json]`
- `pr-pri`: <a id="pr-pri"></a>the PR priority queue the Sweep Manager works top down (`~/.stack/pr-priority.json`, never git). Owner edits (`add`, `move --top|--up|--down|--to`, `pin`, `unpin`, `remove`, `undo`, `ack`), owner decisions (`accept`, `edit`, `reject`), agent `recommend` (exit `4` when blocked) and `decisions`, SM `list --json --refresh`, `record`, `depends`, `escalate`. See [docs/pr-priority.md](pr-priority.md). `pr-pri list [--refresh] | add <ref> [--rank n] [--note t] | move <ref> --top|--up|--down|--to <n> | pin|unpin|remove <ref> | undo | recommend <ref> --agent a --reason t [--to-rank n] | accept <id> | edit <id> --reason t [--rank n] [--note t] | reject <id> --reason t | decisions [--agent a] | depends <ref> --on <ref> [--remove] | depends --file edges.json [--remove] | record <ref> [--file rec.json] | ack <ref> --thread url --note t | escalate --file set.json` (edits also take `--rev n`) `brief <repo>#<n> [--file brief.json --agent a] [--refresh]` stores or shows the agent brief for an Autopilot PR that waits on you (at most 120 words; `[stale]` after a new push)
- `priorities`: <a id="priorities"></a>the owner priorities report as markdown, read live: QM (one row per project; only on its days), Now (the first 3 open), PRs (live PRs that need the owner, quickest first), Today, Next 3 days. Project rows come only from tiered tasks in `tasks/*.md`: a line that starts with `1️⃣` (today), `2️⃣` (this week) or `3️⃣` (this month), with `(agent: name)`. Columns: Project, Agent, 🤖 Status, 👱‍♂️ Next action. A priority with no tiered task shows a gap row: the CoS who must add one, by when, and the task to add. Each section carries `as of <time>` (stale after 30 min). `priorities [--json]`
- `pris`: <a id="pris"></a>the owner priorities in order (`~/.stack/pris.json`, never git). `pris [--json] | pris seed --file <md> | pris put --file <json> | pris link <id> [--projects a,b] [--keywords a,b] [--refs a,b] | pris note <id> <text> | pris gaps` (seed runs once; `put` replaces the list from a JSON array, where `slot` (0-99) and `days` (`mon`..`sun` to a slot or `off`) set the order of each weekday; `link` sets the terms that link tasks, never editing task files; `note` records status for this week; `gaps` lists priorities with no status, status older than 7 days, or no linked tasks, each with the next command). For the priorities tables a priority may also set `label` (project name), `cos` (the Chief of Staff who owns the project task file; `CoS` without it), `action` (a fixed next action), `session` (the agent session id) `windows` (`[{days, from, to}]`, local `HH:MM`; none means all day) and `perProject` (true: its own first section, one row per project, for QM)
- `remove-completed`: <a id="remove-completed"></a>delete checked rows. `remove-completed [--project name] [--queries] [--no-update]`
- `inbox`: <a id="inbox"></a>reply on a task as an agent, list open instructions, or mark one handled. `inbox reply <ref> --from <agent> --text t [--expect t]`, `inbox list [--project p] [--agent slug] [--state open|handled|all] [--all] [--json]` (`--all` lists every entry, withdrawn ones too; `--agent` adds the messages picked for that agent in any project and skips ones picked for another), `inbox handle <id> [--note t] [--from <agent>]` (see `docs/agent-instructions.md`). `inbox run [--project p] [--once|--watch] [--json]` delivers open messages to their agents: it runs each agent headlessly (`claude -p`), posts the reply in the thread, and marks the entry handled; one line per entry (`<id> <state> <agent> <reason>`); exit 1 while the Claude login is expired (see `docs/agent-instructions.md`, "Delivery"). `inbox sources [--json]` lists each inbox source (every email account, GitHub, planned Teams and Slack), its state, last sync and the exact step to connect it; exit 4 while one needs attention (see `docs/inbox-sources.md`)
- `agent`: <a id="agent"></a>run one prompt on an ACP agent over stdio (e.g. `gemini -- --acp`). Each permission request becomes an ask (`tasks/.stack/asks/perm-*.md`); nothing is auto-allowed. The agent gets an allow-listed environment, never Stack tokens. `agent run <command> [args...] --prompt t [--cwd dir] [--timeout s]` (default 600 s; put `--` before an agent argument that starts with `--`)
- `agents`: <a id="agents"></a>agents per project folder. `agents list [--project p --section s] | add <slug> --name n --scope a,b [--role r --reports-to a --model m --mode long-running|ad-hoc --tools a,b --prompt-file p]`
- `live`: <a id="live"></a>the live validation lane: one PR at a time, its checklist, and the shared server lock (`/tmp/fh-server.lock`). See [live-validation-agent.md](live-validation-agent.md). `live [next [ref] [--agent a --worktree p --offline] | ready <ref> --url u --pid n [--port n --worktree p] | state <ref> preparing|working | checklist <ref> --file items.json [--agent a] | item add|check|uncheck|fail|needs-fix|fixed|block|comment|edit <ref> [id] [--text t --reason r --by b] | resolve <ref> [--reason merged|closed|done]]`
- `update`: <a id="update"></a>regenerate README, stack, projects, my-day (scores and orders like `stack next` by default; `--engine legacy` writes the PowerShell output, see [ranking.md](ranking.md)). After it writes the files, it runs the task lint: with an issue it prints the `lint` lines on stderr and exits 1. `update [--sweep] [--queries] [--engine legacy|stack]`

After `start`, `complete`, `skip`/`park`, `resume`, `suspend`, `retitle`, `remove-completed`, and `add-project` change a file, the CLI runs `update --sweep` (like the legacy scripts). `--queries` also refreshes GitHub query rows; `--no-update` skips the refresh. This refresh does not run the task lint.

## Agents

- `stack inbox reply tasks/<file>.md:<line> --from <agent> --text "..."`: an agent's reply on a task (`tasks/.stack/inbox/<project>.md`, `from: agent`); the owner reads it in the task thread. `stack asks put ... --ref tasks/<file>.md:<line>` ties an ask to a task the same way.
- `stack agents list [--project p --section s] [--json]`: the team (files in `tasks/.stack/agents/` and `.claude/agents/`, plus agents named in a project's `Agents` metadata); with `--project`, the agents whose scope covers it, the roll-up first, then most specific first.
- `stack agents add <slug> --name n --scope a,b [--role r --reports-to a --model m --mode long-running|ad-hoc --tools a,b --prompt-file p]`: write or update `tasks/.stack/agents/<slug>.md`. Scope entries are `project`, `project/section`, or `*`; `--reports-to` names the manager (default: the narrowest agent covering the same projects, else the roll-up). `.claude/agents/<slug>.md` files are read into the team too, never written.
